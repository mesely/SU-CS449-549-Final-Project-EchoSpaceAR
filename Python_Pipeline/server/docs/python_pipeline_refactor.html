EchoSpaceAR • Python Pipeline • Refactor

Readable code, same runtime behavior.

This refactor keeps the original Unity-facing workflow intact, but replaces the old single-file `Pipeline.py` with a cleaner runtime layout. The goal was simple: preserve what the system does, while making it much easier to understand, extend, and debug.

1 Entry point stays the same: `Pipeline.py`.
7 Focused runtime modules under `pipeline_runtime/`.
0 Changes to `Android` and `Quest2_3`.

Refactor rule

Behavior first. The refactor targets naming, structure, comments, duplicate removal, and helper extraction. Audio flow, HTTP contracts, and model integration remain aligned with the original pipeline.

Runtime Flow

How the pipeline moves audio

Unity still sends chunks to the HTTP bridge. The bridge pushes audio into the visualizer, and the visualizer fans the same stream into SPL plotting, YAMNet classification, Whisper STT, and optional Gemini summaries.

1

Unity upload

`/audio_chunk` receives float32 PCM frames and forwards them to the registered sink.

2

Live SPL

The visualizer computes block RMS dBFS and keeps the live matplotlib graph updated.

3

YAMNet

Background workers build rolling windows, infer label probabilities, and publish events.

4

Whisper

Speech-gated sessions use pre-roll buffering so short utterances are not clipped.

5

Gemini

Classifier and STT windows can be summarized into short user-facing environment messages.

Module Map

What each file owns now

The new shape is intentionally boring in a good way: each file has one clear responsibility, so future edits do not require reopening a giant mixed-purpose script.

Launcher

Pipeline.py

A thin compatibility entry point that simply calls the new runtime package.

Configuration

pipeline_runtime/config.py

Central constants, environment loading, optional dependency flags, and path resolution.

Audio I/O

pipeline_runtime/device_utils.py

Audio device listing, default-device selection, and sample-rate helpers.

Models

classification.py + transcription.py + llm.py

Each model integration now has its own class and its own readable control flow.

Orchestration

pipeline_runtime/visualizer.py

Owns queues, worker threads, plotting, session ids, and event publication.

Networking

pipeline_http_bridge.py

Still exposes the same Unity endpoints, but now with smaller handler methods and cleaner event writes.

Before

The old pain points

  • A very large `Pipeline.py` mixed setup, workers, UI, STT, YAMNet, LLM logic, and dead duplicate code.
  • Helper behavior was hard to locate because everything lived in one runtime file.
  • Understanding the HTTP bridge and runtime flow required jumping through long unrelated sections.
After

The refactor wins

  • The entrypoint remains stable while the implementation becomes modular.
  • Short English comments now explain intent where the code was previously dense.
  • Duplicate dead code is removed, and repeated low-level helpers are centralized.

Stable Contracts

What did not change

This matters as much as the cleanup itself. The refactor was designed to be safe for the rest of the project, especially the Unity side.

Same launcher

Existing scripts can still run `python Pipeline.py` without learning a new command.

Same endpoints

`/client_hello`, `/audio_chunk`, and `/events` keep their original job and response style.

Same core behavior

Unity audio is still classified, speech can still be transcribed, and LLM summaries still build on those windows.
